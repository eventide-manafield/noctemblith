# Noctemblith 0.1.2

현재 제품 안내를 녹템블리스로 정리하고 삭제된 역할 알림으로 목록 전체가 실패하는 문제를 함께 수정한다. 런타임은 Node 26.12.1, linux/amd64다. 기존 0.1.1의 단독/통합 모드 및 Account Core 0.1.1 호환 설정을 유지한다. 새 환경변수와 DB migration은 없다.

- 소개 화면은 녹템블리스 이름과 기존 SVG를 사용하며 원작 Misskey 크레딧을 별도로 표시한다. 원작 기여자·번역·후원 링크와 실제 수혜 대상은 바꾸지 않는다.
- 설치, 튜토리얼, 업데이트, 이동 버튼, 게임, 미리보기, 운영 로그, 관리자 메일과 시스템 알림의 현재 제품명을 정리한다. 번역은 Crowdin 관리 파일을 덮어쓰지 않고 fork 전용 계층에서 적용한다.
- 예전 upstream 저장소/문의 기본 주소만 조회 결과에서 녹템블리스 주소로 보정한다. DB를 자동 갱신하지 않는다. 사용자 지정 주소·빈 값·tarball 제공 정책은 보존한다. 새 인스턴스 초기값은 녹템블리스 저장소를 사용한다.
- 서비스워커 번역 JSON의 파일 버전은 앱 자체 버전과 일치시킨다.
- ActivityPub/Misskey API·SDK·인증·JSON-LD·DOM/저장소·파일 형식·기존 경로 식별자와 실적 ID·달성 조건·기존 공유 해시태그는 보존한다. 라이선스·원작 역사·Misskey Hub 등 외부 서비스 고유명도 남는다.
- 삭제된 역할 조회의 EntityNotFoundError만 알림 생략으로 처리하며 정상 알림은 유지하고 다른 DB 오류는 전파한다. 계정·알림 데이터는 삭제하지 않는다.

## 적용

새 digest를 Pull한 뒤 운영자가 기존 설정을 유지하여 Noctemblith 컨테이너만 교체한다. 기존 이미지/digest 및 설정을 보관하면 이미지 교체로 되돌릴 수 있다. 이번 릴리스 제작 과정에서는 Studio/Nexus 서비스를 배포·재시작하지 않는다. 중앙 연결 관리자·모더레이터의 MFA step-up은 여전히 미지원이며 차단된다.

## Jenkins 없는 제작

확정 소스의 기존 Dockerfile runner target으로 linux/amd64를 빌드할 수 있다. 이번 제작은 의존성·OS 변경 없이 이전 알림 핫픽스 digest를 고정 베이스로 재사용하며 Node 26.12.1에서 기존 rolldown/Vite/i18n/SW 빌드를 수행하고 생성 산출물과 변경 소스·버전 메타데이터를 교체한다. 사용한 Dockerfile·베이스 digest·검증 결과는 릴리스 산출물에 기록한다. 개발 인증정보나 인스턴스 설정을 빌드 컨텍스트에 넣지 않는다.
